# 📝 要件定義書 Draft v0.2（アップデート）

## 1. 世界表現

* **2D俯瞰（トップダウン）** で確定
  → 処理負荷が軽く、ユニットが多い今回のゲームに最適
  → WebGPUで大量エージェントの座標更新・判定がしやすい

---

## 2. システムの長期的な方向性

### 🎯 二つの柱（両方満たす）

1. **遊べる・眺めて楽しい RTS / 群衆バトルゲーム**
2. **今後の高度な“離散データシミュレーション・エンジン”の核**

### 🔧 そのための設計方針（重要）

* **アーキテクチャは“機能分割 → ライブラリ化”を前提に構築する**
* Rustの **Traitベースの機能付加** を軸に、
  ユニットへ能力を“注入”する仕組みを設ける
* コアエンジンは「思想的 ECS（Entity Component System）」
  もしくは **Trait-ECS ハイブリッド**を採用する（後で詰める）

---

## 3. 初期バージョン（v0）で実装するユニット

> **v0 から全ユニットを入れる方向で確定**

### ◎ アンドロ側

* ブロッケンJr（最強）
* 四天王（4体）
* アンドロ軍団（遠 / 中 / 近距離タイプ）

### ◎ 人類側

* キャシャーン（最強）
* 人類（大量、装備＋進化あり）
* 指揮階級（将・佐・尉・兵）※将来の機能だがモデル設計段階から考慮

---

## 4. 指揮権（Command Range）システム（将来の主力機能）

### 4.1 ユニット別の指揮範囲

| 陣営   | ユニット    | 指揮権      |
| ---- | ------- | -------- |
| アンドロ | ブロッケンJr | 広範囲      |
| アンドロ | 四天王     | 中範囲      |
| アンドロ | 雑魚      | なし       |
| 人類   | 将       | 広範囲      |
| 人類   | 佐       | 中範囲      |
| 人類   | 尉       | 小範囲      |
| 人類   | 兵       | なし       |
| 特殊   | キャシャーン  | なし（個体最強） |

### 4.2 指揮範囲による効果（予定）

* 指揮領域内のユニットは「指揮力に応じたバフ」を受ける
  （攻撃力UP、連携度UP、視界UP、陣形を乱さない等）

### 4.3 実装方針（重要）

* 今回の v0 では「未実装」
* ただし **データ構造・Trait構造は、将来追加できる形で設計しておく**

---

## 5. コア設計思想（エンジン化に必須）

### 必須の機能分離レイヤ

1. **World Engine**

   * 座標 / 地形 / 時間管理

2. **Physics / Collision Engine**

   * 移動 / 当たり判定

3. **Battle Engine**

   * 射撃・近接攻撃・ターゲット選定

4. **AI・意思決定（Behavior Engine）**

   * アンドロ軍団（単純ルール）
   * 人類（知性・陣形）
   * キャシャーン（高レベルAI）

5. **Trait-System（能力付加）**

   * 射撃可能
   * 剣攻撃可能
   * 指揮可能
   * 視界拡張
   * 進化可能
   * 連携可能
     などを柔軟にユニットに付加できる構造。

6. **進化システム（人類専用）**

   * 時間×経験×開発力で強化

7. **WebGPU計算カーネル**

   * 座標更新
   * 索敵距離判定
   * 弾道計算
     など GPU にふれる処理の最適化ポイント。

8. **UI / 可視化レイヤ**

   * TS/JS によるインタラクションと描画

# 🔥 要件定義 v0.2 → さらに詰めるべき論点（質問 第2弾）

この段階で最も整理が必要なポイントは **Trait の粒度（細かさ）** と **ECSとの境界線**。

以下、たねちゃんに決めてもらいたい：

---

## ❓ Q1：ユニットの「能力」は Trait で実現する？

（例）

* **Moving**：移動できる
* **MeleeAttack**：近接攻撃
* **RangedAttack**：射撃
* **HeavyCannon**：大砲
* **CommandAuthority**：指揮権
* **Evolving**：進化
* **Intelligent**：陣形行動
* **HeroicAI**：キャシャーンの特別AI
* **SwarmAI**：アンドロ軍団の単純ルール

こういう能力 Trait を
**細かくする（小さい部品） vs 大きくまとめる（抽象的部品）**
どっちが理想？

---

## ❓ Q2：行動ルールはどれくらい抽象化する？

例：アンドロ軍団

* **A案：単純ルールで完結（Seek→Attack→Repeat）**
* **B案：DNA的ルール（周囲3セルの状態で行動決定）**
* **C案：もっと複雑にして進化可能にする（群知能）**

どれ？

---

## ❓ Q3：キャシャーンのAIはどうしたい？

* **A：超単体最強、特殊ロジックで動く“ヒーローAI”**
* **B：汎用的な AI モジュールを流用し、チューニングで強い存在にする**
* **C：将来的には RL や木探索などを入れる前提で、拡張可能にしておく**

---

## ❓ Q4：人類側の「進化システム」はどうモデル化する？

* 時間経過でレベルアップ
* 資源（倒した敵？製造ポイント？）で兵器開発
* 陣形成功率の向上
* 新しい兵科のアンロック

どの方向にしたい？

---

ここ決めると “最上位の抽象構造” が固まるから、
Rust のTrait設計にも WebGPU側の負荷設計にも大きく影響する。
