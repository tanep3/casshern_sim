## 🏗 UI Draft v0.6 反映内容

### 1. グリッド＆視界設定（Q12）

* **セルサイズ**

  * `cell_size = max_vision_range / 2` とする。
* **なぜ「視界そのもの」じゃなくて 1/2？**

ざっくり言うと：

* 目的は
  **「自分の視界内にいる敵だけを、少ないセルチェックで見つける」**
* グリッド法のセオリーは：

  * セルサイズを視界より**大きく**すると
    → 探索対象セルが増えて計算が重くなる
  * セルサイズを視界より**小さくしすぎる**と
    → セル数が増えすぎて管理コストが上がる

`cell_size = vision` だと：

* 視界が「1セル＋隣8セル」では**ギリギリ漏れるケース**が出る
  （セル境界またぎのとき、最大距離が視界と同じになるため）

`cell_size = vision / 2` だと：

* 「同じセル or 隣接セルにいるユニット」は
  **距離が確実に「視界以内の候補」**になる
* チェックするセルは最大で 5x5（それでも十分少ない）

なので、

> 「視界そのもの」でも動くけど、
> **“漏れない & 無駄が少ない”安定ラインが 1/2 前後**

ってイメージ。
※ 実装時は `cell_size = max_vision_range / 2` をベースに固定でOKにしておく。

### 2. ワールドサイズ（Q13）

* **固定マップ** を採用。
* **ワールド座標系 = ブラウザの描画領域（Canvas or WebGPUのViewport）**

  * 例：`width = 1920`, `height = 1080` なら、そのままワールドサイズにする。
* メリット：

  * 座標変換がシンプル（= ピクセル ≒ マップ単位）
  * スクロールやカメラ制御を考えなくてよい（v0では特に）

※ 将来、「ワールドは広くて、画面はその一部だけを映す」モードに拡張する余地は残したままで設計しておく（つまり内部的には world_size と viewport_size を分ける）。

### 3. AI計算の頻度（Q14）

* **AI更新頻度 = 3 tick に1回** をデフォルトにする。

  * 例：60FPS 換算なら、AIは 20回/秒 更新。
  * 見た目は十分“リアルタイムぽく”見える。

* これは **設定で変えられるようにする**：

  ```text
  AI_UPDATE_INTERVAL_TICKS
    - 1 → 毎tick（最大負荷／最も滑らか）
    - 3 → デフォルト（軽量・自然）
    - 5〜10 → 負荷がきついときの緊急モード
  ```

* タルモン案としては：

  * **ヒーロー（キャシャーン）やボス格だけ毎tick**
  * 雑兵や遠距離ユニットは 3〜5tick に1回
    みたいな「レベル・オブ・ディテール（LOD）」も
    UI v1.x 以降で狙えるようにしておく。

* 「CUDAでも追いつかないかも」の懸念について：

  * 10万体規模で

    * グリッド分割
    * 3tickに1回AI
    * 他のtickは移動＆攻撃のみ
      にすれば、かなり現実的な負荷に収まるはず。
      最悪、**AI_UPDATE_INTERVAL_TICKS を上げるだけで生還できる設計**にしておくので、そこは安心して良いと思う。
