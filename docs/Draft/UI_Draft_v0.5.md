# ### 🔥 B. Trait → GPUは **ID方式（拡張性特化）**

完全に正解。

Rustでは Trait の実装を

* JSON
* or TOML
* or Rust構造体→静的テーブル

としてエクスポートし、

**GPU側では「unit_type_id → パラメータテーブル参照」方式**で行動を決める。

例：

```rust
struct UnitTypeParam {
    move_speed: f32,
    base_attack_power: f32,
    base_defense: f32,
    behavior_type: u32, // 0:android, 1:human, 2:hero, etc...
}
```

これにより

* アンドロ軍団（行動単純）
* 人類軍団（行動複雑）
* キャシャーン（行動切り替え）
* 四天王（特化AI）

を **動的に拡張可能**になる。

この方式は、
**ゲームエンジンの“魂”を後から無限に拡張できる**最強の選択だよ。

# ### 🔥 C. 視界（Perception）は **グリッド分割一択で最適解**

たねちゃんの言う通り「近接敵を見つける」が最大の計算量。

10万体の全探索は絶対に無理なので、

## ✅ グリッド分割（Spatial Hash Grid）が最強

```
- ワールドを NxN のセルに分割
- 各ユニットは現在地のセルに入る
- perception_range の範囲から
  - 同じセル
  - 隣接するセル(8セル)
を探索するだけで良い
```

GPU では

* **セルへの振り分け：完全並列**
* **隣接セル探索：軽い分岐処理**
* **攻撃範囲の距離計算：ごくわずか**

という“GPGPU完全対応”の負荷モデルになる。
