# 🏗 暫定システムアーキテクチャ（UI Draft v0.1）

ここから、たねちゃんが言ってた **「暫定版UI」** に入るね。
まだ実装じゃなくて、**モジュールとデータの流れを俯瞰整理したレイヤ**。

## 1. 大きなレイヤ構造

1. **Core Simulation Engine（Rust + WASM）**
2. **Rendering & UI Layer（JS/TS + WebGPU or Canvas）**
3. **Config & Scenario Layer（初期条件・パラメータ定義）**

---

## 2. Core Simulation Engine の内部モジュール

### 2.1 World / State モジュール

* 世界の状態を管理：

  * ユニット一覧（巨大配列 or バッファ）
  * 地形情報
  * 時間（tick カウンタ）
  * TechLevel（人類側の進化状態）
* 提供する主な機能：

  * `step()`：1 tick 進める
  * 初期化（ユニット生成・配置）
  * Restart 用のリセット

---

### 2.2 Entity / Trait モジュール

* 共通ユニット構造体（さっきのベース情報）
* 各種 Trait インターフェース：

  * 移動系・戦闘系・知覚系・AI系・指揮系・進化系…
* Archetype / Faction / Rank の定義
* 将来的に：

  * ECS 的な構造（Component 配列）に寄せるか、
  * Trait 実装ベースの構造体群にするかは、このレイヤで吸収。

---

### 2.3 AI / Behavior モジュール

* 各種 AI Trait の実装：

  * `SimpleAggressiveAI`（アンドロ軍団）
  * `TacticalHumanAI`（人類）
  * `HeroBehavior`（キャシャーン）
* キャシャーンのモード切替はここで管理：

  * Mode = { 突撃, 援護, 殲滅 }
* 大量ユニット数を考慮して：

  * 人類 10万体は“全員フルAI”ではなく、
    **まとめて「小隊AI」的に扱う可能性も視野に入れておく**
    （←ここは後で詰めるポイント）

---

### 2.4 Combat / Physics モジュール

* 移動更新（位置・速度）
* 当たり判定：

  * 近接範囲
  * 射程判定
* ダメージ計算：

  * attack_power / defense_power / 装備 / 指揮バフ などを反映
* HP更新と死亡処理

ここは **WebGPU カーネルに乗せたい処理の最有力候補**。
（最初は CPU で動かしてからオフロードでもOK）

---

### 2.5 Evolution / Tech モジュール（人類専用）

* 時間に応じた TechLevel 更新
* TechLevel に応じた兵器アンロック
* Unlock 情報を UI レイヤへ通知するフックを持つ

---

### 2.6 Victory / Control モジュール

* 全滅判定（アンドロ／人類）
* 勝利／敗北ステータス
* Pause / Resume / Stop / Restart の制御フラグを保持
  （UIレイヤからの指示を受ける窓口）

---

## 3. Rendering & UI Layer（JS/TS）

### 3.1 描画レイヤ

* WebGPU or Canvas での 2D 描画
* 必要情報：

  * 各ユニットの位置・陣営・種別
  * 生存状態
* 色とサイズルール：

  * アンドロ軍団：赤（小）
  * 人類軍団：青（小）
  * ブロッケンJr：紫（大）
  * 四天王：赤＋一回り大きい or 別枠（詳細はあとで）
  * キャシャーン：白（大）

---

### 3.2 UI / 状態表示

* キャシャーンモードボタン（突撃／援護／殲滅）

  * 現在モードを目立つ場所に表示
* 兵器アンロックエリア

  * 新兵器追加リスト
* 通知エリア

  * 「兵器XXXがアンロックされました」
  * 「アンドロ軍団残存：XXX」「人類残存：YYY」なども将来表示可
* シミュレーション制御ボタン

  * Pause / Resume / Stop / Restart

---

## 4. Config & Scenario Layer

* ユニット数：

  * ANDRO_COUNT, HUMAN_COUNT
* 初期配置パターン：

  * 正面衝突型
  * 包囲型
  * ボス中央配置 etc.（将来）
* パラメータプリセット：

  * 「圧倒的アンドロ優勢」
  * 「ぎりぎりバランス」
  * 「人類の奇跡的逆転狙い」
    などのプリセットシナリオも将来用意可能。

## ❓ SA-Q1：

**人類10万体は「全員 個別ユニット」として扱うイメージ？
それとも、ある程度は「小隊単位（例：30人1ユニット）」に集約してもよい？**

* A. **全員 個別ユニット**

  * 完全に1体ずつ位置・行動・装備を持つ
  * 表現力は最大だけど、計算コストも最大
* B. **小隊ユニット化あり**

  * 見た目は多く見せつつ、中身は「小隊単位」で扱う
  * 例：

    * 1小隊 = 20〜50人
    * 小隊ごとに「隊長」「位置」「射程」「人数」だけ更新
  * 群としての挙動にフォーカスしやすい

どっち寄りを「理想」としておきたい？

（※ 設計上の前提としてだけ決めておきたい。実装は段階的でOK）

## ❓ SA-Q2：

**ゲーム開始時に設定できるパラメータの候補**として、
絶対入れたいのはどれ？

例えば：

* ANDRO_UNIT_COUNT
* HUMAN_UNIT_COUNT
* 人類進化スピード（TechLevelの上がりやすさ）
* アンドロ攻撃力補正
* 人類攻撃力補正
* キャシャーンの強さ倍率
* 地形の有無（フラット／障害物あり）

**「ここは絶対スライダーにしたい」**という項目があれば教えてほしい。
