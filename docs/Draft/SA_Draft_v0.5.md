# 📝 暫定要件定義書 Draft v0.5

## 1. 世界・目的

* **2D俯瞰の戦場**で、
  アンドロ軍団 vs キャシャーン＆人類軍団 の戦闘をシミュレートする。

* 目的は二重構造：

  1. 「眺めて楽しい・ちょっと遊べる」戦闘シミュレータ
  2. 将来的に汎用化可能な **離散データシミュレーション／群衆戦闘エンジン**

* 実装技術（想定）

  * Rust（ロジック）
  * WASM（ブラウザ実行）
  * WebGPU（大量ユニットの並列処理）
  * JS/TS（UI・描画制御）

---

## 2. ユニット共通ベース構造（全キャラ共通）

全ユニットは、最低限として以下の情報を持つ：

* **id**：ユニークID
* **faction**：陣営

  * ANDRO
  * HUMAN
  * SPECIAL（キャシャーンなど）
* **archetype**：キャラクタ種別

  * ANDRO_BOSS_BROCKEN
  * ANDRO_ELITE_FOUR
  * ANDRO_GRUNT_RANGED / MID / MELEE
  * HUMAN_GENERAL / HUMAN_OFFICER / HUMAN_SOLDIER …
  * CASSHERN
* **position (x, y)**
* **direction**（向き）
* **hp / max_hp**
* **base_move_speed**
* **attack_power**（攻撃力）
* **defense_power**（防御力）
* **command_power**（統率力：指揮系ユニットのみ有効。それ以外は0か未使用）
* **equipped_weapon**（現在装備中の兵器／素手／なし）
* **equipped_armor**（防具／甲冑／なし）
* **equipped_vehicle**（戦車・車・バイクなど／なし）
* **alive_flag**
* **control_mode**

  * AI_CONTROLLED
  * PLAYER_CONTROLLED（キャシャーンのみ）

※ 武器・防具・乗り物は「別オブジェクト」として定義しつつ、
　ユニット側には「現在何を使っているか」だけを持たせる。

## 3. 種別・階級・Trait の関係

* **archetype**：
  「このキャラは誰か？」を表すラベル（enum 的なもの）。

* **rank（階級）**（人類向け属性）：
  将 / 佐 / 尉 / 兵 … など。
  ただし、階級だけではなく、

  * HasCommandAuthority Trait と組み合わせた時に
    **「どんな指揮権を持つか」** が決まる。

* **Traits**：
  「このキャラは何ができるか？」を表す能力インターフェース。

### 主な Trait の抽象カテゴリ

* 物理系

  * `Movable`（移動できる）
  * `Collidable`（衝突判定対象）

* 知覚系

  * `PerceivesEnemies`
  * `PerceivesAllies`
  * `HasVisionRange`

* 戦闘系

  * `MeleeAttackCapable`
  * `RangedAttackCapable`
  * `TargetSelectable`（ターゲット選択ロジック）
  * `Defensible`（防御行動）

* 指揮・連携系

  * `HasCommandAuthority`（指揮権：範囲＋バフ強度）
  * `Commandable`（指揮の影響を受ける）
  * `FormationMember`
  * `FormationLeader`

* 行動AI系

  * `SimpleAggressiveAI`（アンドロ用：探す→移動→攻撃）
  * `TacticalHumanAI`（人類用：探す→考える→陣形→移動→防御→攻撃→装備選択）
  * `HeroBehavior`（キャシャーン用：モード切り替え可能AI）

* 装備・兵器系

  * `CanEquipWeapon`
  * `CanUseVehicle`
  * `CanDeployTrap`

* 進化・開発系（人類側）

  * `EvolvesByTime`（時間経過でTechLevel上昇）
  * `UnlocksNewTech`（兵科・兵器のアンロック）

## 4. 陣営ごとのキャラと性格づけ

### 🤖 アンドロ軍団

* **ブロッケンJr**

  * 最強パラメータ
  * 将来的に `HasCommandAuthority`（広範囲）を持つ
* **四天王**

  * 中ボス4体
  * 将来的に中範囲の指揮権を持つ
* **雑魚アンドロイド（遠・中・近距離タイプ）**

  * 攻撃力高く、行動ルールは単純
  * 「探す → 移動 → 攻撃」で十分

→ 並列計算しやすい「単純高火力部隊」。

---

### 🧑‍🤝‍🧑 人類軍団

* **キャシャーン**

  * 全ユニット中、単体最強
  * `HeroBehavior` により

    * 突撃モード
    * 援護モード
    * 殲滅モード
      を切り替えられる

* **人類一般兵・指揮官**

  * 個々は脆い
  * 知性・陣形・環境利用・兵器選択で戦う
  * 階級（将・佐・尉・兵）と、
    指揮権 Trait（将来）で連携強化

* **進化システム**

  * 時間経過で TechLevel が上がり、
  * 新兵器・新しい移動手段がアンロックされる
  * 兵はアンロック済みの兵器から
    **状況に応じて適切な武器を選択・装備／脱着**する
    （例：近距離戦で戦車装備は逆効果 → AIが不適切と判断しやめる）

## 5. UI 要件（v0 時点）

### 5.1 キャラクタ描画

* キャラは **小さなブロック（タイル）表示** で良い。
* 階級持ち／ボス格は **一回り大きいブロック** で描画。
* 色分け：

  * アンドロ軍団：**赤**
  * 人類軍団：**青**
  * ブロッケンJr：**紫**
  * キャシャーン：**白**
* 将来、簡単な凡例（Legend）表示があると親切。

### 5.2 キャシャーン操作 UI

* 画面上に **行動モードボタン** を配置：

  * 「突撃」
  * 「援護」
  * 「殲滅」
* 初期モードは **殲滅**。
* 現在のモードは

  * 画面のどこか（ステータスエリアなど）に**常に表示**する。

### 5.3 兵器アンロック UI

* 画面の一部に **「兵器アンロックエリア」** を用意。

  * 最初は何も表示されない。
  * 時間経過などで兵器がアンロックされるたびに、
    **その兵器がリストに追記表示**される。
* 同時に、

  * **状況通知エリア** に
    「新兵器 XXX がアンロックされました」
    のようなメッセージを表示。
* アンロック済み兵器は、人類側 AI が

  * 距離・地形・敵タイプなどを考慮して
  * 適切な兵器を選び・装備・脱着する
    （近接戦で戦車は逆効果 → 避けるロジックを組む）。

### 5.4 シミュレーション制御 UI

* **Pause（停止）**
* **Resume（再開）**
* **Stop / End（この戦闘を終了）**
* **Restart（同条件でやり直し）**

→ 決着がつかない場合でも
　いつでもユーザーが制御できることを保証。

## 6. 勝敗条件

* **どちらかの陣営が全滅した時点で決着**

  * アンドロ全滅 → 人類勝利
  * 人類全滅 → アンドロ勝利

* v0 では、時間制限や引き分けは考慮しない（将来拡張可）。

## 7. 汎用エンジン化の方針（重要な抽象概念）

将来、アンドロ／人類という具体テーマを離れても使いまわすために：

* 「アンドロ専用」「人類専用」という書き方は避け、
  すべてを **Trait + Archetype + Faction** で表現。
* AIロジックも

  * 「アンドロ用AI」「人類用AI」という実装ではなく、
  * `SimpleAggressiveAI` / `TacticalAI` / `HeroAI`
    のような **抽象 AI Trait** として設計する。

→ これにより、

* 別の世界観（ゾンビ vs 魔法使い、宇宙艦隊 vs 惑星防衛軍など）にも

  * そのまま流用しやすくなる。

# 👍 タルモンの現時点評価

* 情報量は多いけど、
  **すべてが「抽象レイヤ」として綺麗に分離できている**ので、
  Rust + WASM + WebGPU 前提でも、設計としては全然いける。
* 実装時は

  * Trait とベース構造を先に固めて
  * 中身のロジックは段階的に入れていく
    形にすれば、破綻しない規模感。
