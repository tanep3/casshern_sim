# 🔥 ターンループの結論（タルモンの確信）

**✔ 各ユニットの行動（AI・移動・攻撃）は WebGPU 上で “完全並列実行” にすべき。**

CPU は

* UIまわり
* 勝敗判定
* 時間管理
* アセット読み込み
* WebGPUへのバッファ更新

だけを担当し、

**ユニットの哲学（AI）と物理行動（移動・攻撃）は、全部GPU側に押し込む。**

これが正解。

# 🎯 ゲームループの“GPU版”を再構成するとこうなる

## **【CPUフェーズ】**

1. UI入力を取得
2. パラメタをGPUへ push
3. シミュレーション tick の進行
4. 描画命令発行（レンダリング）
5. 一部の集計（死亡数・進化レベル・勝敗判定）

## **【GPUフェーズ】（1tick中の中核処理）**

GPUのコンピュートシェーダ上で並列実行：

### ① Perception（知覚）

* 各ユニットが視界内の敵・味方をブロードフェーズ＋ナローフェーズで並列探索
* Small buffer（※個々の最重要ターゲット情報）に格納

### ② AI（意思決定）

各ユニットは GPU 内で：

* 行動モード（突撃／援護／殲滅）
* 距離・位置
* 自分の兵科（Trait）
* 小隊情報（隊長の統率バフ）
* アンロック済武器の内部評価

これらを用いて GPU が

> **自分の行動ベクトル（移動方向・目標ターゲット・攻撃種類）を算出**

### ③ Movement（移動）

* 移動ベクトルにもとづき位置を並列更新

### ④ Combat（攻撃）

* 射程判定
* 命中判定
* ダメージ算出
* HP更新

※このあたりは GPGPUの典型的並列パターンでいける。

### ⑤ Post-processing（後処理）

* 死亡フラグ
* 小隊人数減少カウント
* キャシャーンのモード参照

# 🔍 **質問B：Trait → GPU シェーダ変換方式はどれにする？**

1. **固定フラグ方式（軽量・高速）**
   Trait ごとにビットフラグ割り当て
   GPU側は `if (trait & FLAG_MOVE_FAST) { ... }` 方式

2. **ID方式（拡張性重視）**
   `unit_type_id: u32` を GPU に渡し
   GPU側はテーブル参照で行動決定
   （柔軟で後から増やせる）

3. **軽量DSLを自動生成する方式（最強・難度高）**

   * Rust Trait
   * → TOMLなどの中間表現
   * → GPUシェーダコードへ自動書き換え
