# 📋 要件定義書 (Requirements Definition)

## 1. プロジェクト概要
本プロジェクト「Casshern Sim」は、Rust, WASM, WebGPUを用いた高性能な2D戦闘シミュレータである。
最大10万体のユニットが入り乱れる壮絶な戦いを、**WebGPU Compute Shaderによる完全並列AI**で実現する。
プレイヤーはキャシャーンの操作や兵器の管理を通じて戦局に介入し、圧倒的な物量と個々の自律行動が織りなすドラマを体験する。

## 2. ステークホルダー要件
### ユーザー（プレイヤー）
*   **圧倒的な物量感**: 10万体のユニットが個別に判断して動く様を見たい。
*   **戦局への介入**: キャシャーンを直接操作、またはモード指示で動かし、戦況を変えたい。
*   **戦略的選択**: 人類軍の兵器をアンロック・装備させ、戦術の変化を楽しみたい。
*   **カスタマイズ**: ユニット数やAI計算頻度を調整し、自分のPCスペックに合わせたシミュレーションを行いたい。

### 開発者
*   **GPU中心設計**: AIロジックをCompute Shaderで実装し、CPU負荷を最小限に抑えたい。
*   **データ指向**: ユニットデータの正本をGPU上に置き、高速なシミュレーションを実現したい。

## 3. 機能要件 (Functional Requirements)
1.  **GPU完全並列AI**:
    *   移動、攻撃、探索、ターゲット選択などの全AIロジックをWebGPU Compute Shaderで実行する。
    *   **アンドロ軍団**: 恐怖を知らず人類を殲滅する単純・高火力AI。
    *   **人類軍団**: 「フェーズ（序盤・中盤・終盤）」、「小隊指揮（階級・指揮範囲）」、「士気」に基づく複雑なAI。
    *   **キャシャーン**:
        *   **3つのAIモード**:
            *   **殲滅 (Annihilate)**: 全視野で最も近い敵を捕捉・攻撃する（デフォルト）。
            *   **突撃 (Assault)**: ブロッケンJrや四天王などのボスを優先的に察知し、そちらに向かう。ボス不在時は敵の群れている方向（重心）へ突撃する。
            *   **援護 (Support)**: 苦戦している人類ユニットを発見し、その場所へ救出に向かう。
        *   **全視野**: グリッド制限を超え、マップ全体のユニットを認識可能とする。
2.  **大規模レンダリング**:
    *   最大100,000体のユニットを描画。描画パイプラインはAI計算パイプラインと分離する。
3.  **小隊・士気システム** (Future Extension):
    *   **※本バージョンでは実装を見送り、将来の拡張機能とする**。
    *   人類軍は小隊（Squad）を組み、階級（将・佐・尉）を持つ指揮官が率いる。
    *   指揮官の死亡や戦況悪化により「士気」が変動し、逃走や突撃といった行動変化を引き起こす。
4.  **兵器進化システム (Evolution Gauge)**:
    *   シミュレーションの経過時間（Tick数）に応じて新兵器（Spread Gun, Sniper, Melee）が自動的にアンロックされる。
    *   進化状況をUI上のゲージで可視化する。
5.  **コンフィグレーション**:
    *   **初期ユニット数**: アンドロ・人類それぞれ1〜100,000体まで設定可能。
    *   **AI計算間隔**: ユーザー設定可能（デフォルト3 tick）。
    *   **バランス調整**: ユニットダメージや移動速度比率をスライダーでリアルタイム調整可能。
6.  **戦局可視化**:
    *   **フェーズシステム**: 人類軍の残りHP比率に基づき「EARLY (>70%)」「MID (30-70%)」「LATE (<30%)」へと不可逆的に進行させる。
    *   フェーズ進行により人類AIの好戦性が変化する。

## 4. 非機能要件 (Non-Functional Requirements)
1.  **パフォーマンス**:
    *   10万体シミュレーション時でも60fpsを目標とする。
    *   視界探索範囲を「視界半径の1/2」とし、グリッド分割もこれに合わせることで近傍探索を高速化する。
2.  **アーキテクチャ**:
    *   **Unitデータの正本はGPUバッファ(SSBO)に置く**。CPU側は初期化とデバッグ表示のみ。
    *   ロジックはWGSLで記述し、WASMはコントローラーに徹する。

## 5. 受け入れ基準 (Acceptance Criteria)
*   [ ] 10万体のユニットが設定されたFPSで動作すること。
*   [ ] 小隊長が倒された際、部下ユニットの挙動（士気低下）が変化すること。
*   [ ] 兵器を変更した瞬間、ユニットの攻撃挙動が変わること。
*   [ ] キャシャーンを操作した際、AIよりもプレイヤー入力が優先されること。
*   [ ] 設定したAI計算間隔通りにロジックが実行されること。

## 6. リスクと対策
*   **リスク**: WGSLのデバッグが困難。
    *   **対策**: 開発初期は少数のユニットで動作確認し、計算結果をCPUにリードバックして検証する仕組みを用意する。
*   **リスク**: 複雑な小隊ロジックによるGPUスレッドの発散（Divergence）。
    *   **対策**: 小隊IDでソートしてメモリ局所性を高めるなどの最適化を検討する（v1以降）。
